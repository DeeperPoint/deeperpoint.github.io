Domain wiki → everything

A generic knowledge input, not manufacturing-specific. Fill it for any vertical and it drives the whole system's configuration: wiki_to_vocab.py derives vocab.generated.yaml, which seeds CommonContext's tag vocabulary and every vertical's participant schema. mfgllmwiki is simply the manufacturing instance.

CommonContext

Turns curated documents and wiki pages into an embedded reference_library (pgvector). Vertical-agnostic — the shared knowledge engine Cosolvent's AI features read from at match time.

ClientSynth (source-available)

Generates coherent synthetic populations to bootstrap, test, and demo a market. Apache-2.0 with additional synthetic-data terms — its source is available, but it is not an OSI-approved open-source license. Its output is marked is_synthetic and only ever populates a test/demo instance.

Cosolvent — the shared backend

MIT-licensed headless engine, one of the four DeeperPoint Suite tools. A deterministic compiler reads marketplace.yaml and emits schemas, routes and migrations; the runtime does the pgvector matching. Both the live and the test/demo instances run on this one engine and config.

The vertical alignment layer

The added system layer that aligns the DeeperPoint Suite with a specific application vertical. capacity-exchange-demo is one instance — the market-specific front end users touch, forked from the shared Marketforge_digital_twin shell. Swap this layer + the vertical YAML and the same suite serves a new market.

Two populations, one firewall

Real users sign up through the alignment layer into a live market that starts at zero synthetic users. Synthetic profiles only ever reach a test/demo instance. The provenance firewall — layered watermarking (is_synthetic and a content-hash Merkle root today; cryptographic signatures are planned) with ingest-time verification — is what guarantees the two never mix.

The four core engines — wiki, CommonContext, ClientSynth, Cosolvent — are the DeeperPoint Suite; the alignment layer adapts them to one market. Derivation chain: domain_schema.yaml → vocab.generated.yaml → capacity_vocab.generated.yaml / capacity_schema.yaml → clientsynth_import.yaml + marketplace.yaml. Engines are separate repos; the YAML artifacts are the contract surface between them, and the provenance firewall is the boundary between synthetic and live data.
