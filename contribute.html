Open to Anyone Who Wants In

DeeperPoint is a self-funded, pay-it-forward project with no investors and no board. The engine is MIT-licensed, nobody is locked in, and the work is done in the open. If you want to take part, this is where help lands.

Help that is not code

  • Knowledge of a market. A regulation, a standard, a certification route, the way deals really get done in a sector you know. That is what a market’s domain wiki is built to hold.
  • A market. If you work in a thin market and would let it be a test bed, say so.
  • Judgment. Read a catalog entry or a teardown and say where it is wrong. Candid assessment is worth more than encouragement.
  • Words. The cards, the catalog and the blog all take editing, and every page on this site can be improved.

How to start

  1. Read the fifteen cards for the short version of the thesis, or the whitepaper for the full one.
  2. Pick the repository and open an issue describing the problem, the expected behaviour and the scope, before writing code.
  3. Follow the contributor guide: one change set per pull request, tests and docs with it, the quality gate passing.
  4. For anything that is not code, or to ask before you start, write to the founder from the About page.

Where help is wanted

A new market now starts with its knowledge: a sourced wiki of the market, and a question page that lets people ask it. A digital twin, and later a marketplace, are built on that. The pieces below are not built yet, and each is small enough for one person to pick up.

  • A starter kit for a new wiki. The folder layout, the configuration and a skeleton of rules, created by one command.
  • A status view for research notes. Structured headers on notes that are waiting for a decision, and a script that lists what is waiting on the market’s sponsor.
  • The guarded export, packaged. The step that publishes only pages marked as shareable, and stops if one would carry something that must not leave, made reusable for any wiki.
  • A count of the ways through. Most tasks in a market have more than one way through them. A check that reads the paths recorded for each task and reports which have only one, or none found.
  • The question page, separated from its first wiki. So that it can be put over any wiki.
  • Mining the question log. Turning the questions a wiki could not answer into the next research items.
  • A tested schema proposal. CommonContext can propose a domain schema from documents. It has not yet been run on a wiki’s pages.
  • A two-way drift report. Terms the wiki uses that the schema lacks, and schema values that no wiki page backs.
  • A read-only curator’s view. What is waiting, what was held back and what each publish changed, for someone who is not a developer.

The wiki engine is public, inside MarketForge, so for the wiki tools the first step is an issue there. The question page is not yet in a public repository; to take that one on, write to the founder from the About page. What MarketForge is →

What this page asks for is work and judgment, not money. Cosolvent and CommonContext are free to adopt, fork and build on, and they stay that way: the only costs anyone carries are their own build and operations.
